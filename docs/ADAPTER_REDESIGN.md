## 调整原因

用户已在 Inspect 的 UI Automation / Raw View 下确认：指定独立窗口只有 Weixin 窗格。
当前 windows_uia 要求每行有稳定 AutomationId、发送者和完整 ISO 时间，
这些要求未在客户端满足。停止继续要求用户填写这些字段。
windows.example.toml 已填入实测标题、消息列表和输入框标识，保持 verified=false。

## 自动收发的建议架构

采用独立 Windows 测试环境和专用测试微信账号。该环境用于验证接入后端，
独立环境本身不解决版本兼容，也不代表已经完成自动接入。

1. **入站**：优先验证能提供真实会话标识和消息标识的后端，例如候选中的本地数据库读取。
   只订阅已明确绑定的测试会话，收到原始事件后先做白名单过滤，再交给模型。
   不以昵称、正文哈希或 UIA RuntimeId 作为稳定身份。
2. **身份绑定**：通过后端联系人信息确认实际账号标识，建立「本地会话 ID → 后端会话标识」映射。
   窗口标题仅是展示和辅助检查。同名结果不得自动选择。
3. **出站**：单独验证已选版本和定向发送能力；默认关闭后端自带的主窗口搜索、
   全局快捷键及自动 OCR 降级。只有经过检查的目标发送路径才能挂到 SessionGate 后面。
   无法提供可靠目标定位时，停止该后端的自动发送验收。
4. **权限边界**：若读取库需要打开整份联系人/消息数据库，必须明确说明实际访问范围；
   后端查询只选白名单不等于底层只访问了白名单数据。因此优先使用专用测试账号。
5. **内核**：继续复用 Message / Engine / Store；不同后端使用不同 source。
   明确后端消息 ID 的作用域，组合账号、会话和原始 ID；时间采用后端原始时间，
   不把展示时间或程序接收时间冒充原始发送时间。
6. **开关**：SessionGate 默认关闭；启停产生独立运行世代，关闭后旧事件和旧回复不可继续发送。
   若后端运行在独立进程，增加带过期时间的运行许可；管理进程失联时停止发送。
7. **回执**：分别记录请求提交、本地发送证据、对端收到。无法证明已发送时进入 uncertain，
   不自动重发。后端返回 True 不足以构成对端送达证据。

界面将由填写 AutomationId 改为「后端状态 → 绑定真实测试会话 → 白名单 → 开关」。
后端没有通过验证前，不增加一个显示“已连接”的空接口。

## 在当前日常微信上的替代方式

若用户不采用独立测试环境，可选择人工确认的辅助模式：用户提供测试消息，
内核生成草稿，用户在微信中自行确认接收方并发送。
该模式不依赖 UIA，不自动操作其他窗口，但明确不属于自动接收/自动发送。
是否采用此模式需由用户选择，不能擅自把原自动化需求降级。

## 验收顺序

1. 固定后端版本、微信版本、包哈希，确认实际 API 与初始化副作用。
2. 只读绑定一个测试联系人，取得真实消息/会话/发送者 ID；不启动发送。
3. 注入合成事件验证白名单、类型隔离、同正文不同 ID、去重、过期、重启世代和关闭竞态。
4. 明确指定测试文本与对端，进行一次受控真实发送并由对端确认。
5. 测试断线、发送后失联、目标失配和紧急停止；非白名单发送调用次数必须为零。
6. 通过后才启用持续 Echo 收发；群聊与真实模型另行验收。
