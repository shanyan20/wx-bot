# 微信 Bot 完整测试说明

> 当前版本已按用户验收结果切换为双联系人自动回复，操作以 [双联系人自动回复测试更新](AUTO_REPLY_REPORT.md) 为准。白名单限定“憨憨的小憨憨”“shanyan”，启动后不再逐条确认发送。下文保留此前分阶段人工验收说明，供历史记录对照。

适用版本：0.2.0rc1。适用项目：E:/project/bot。
本说明覆盖本机 Windows、个人微信、独立测试窗口、文字/图片和 DeepSeek 模型的人工验收。
本次使用 **scripts/acceptance.py**，不要误用旧 scripts/control.py 或 mock 运行入口。

## 1. 测试目标与判定原则

系统应只读取和回复白名单联系人/群聊；不同会话分列显示、上下文隔离。
每条消息作为独立验收样本，分三项判定：

| 阶段 | 实际动作 | 必须展示的输出 | 人工通过条件 |
|---|---|---|---|
| A 读取 | 从已绑定会话读取原生消息和媒体 | 发送者、时间、类型、文字/图片、消息键、失败原因 | 与微信原消息一致，图片是该条消息的真实内容 |
| B 模型 | 把 A 已审阅内容和本会话历史发给模型 | 模型名、本次输入、实际回复 | 请求属于正确会话，模型回复可用且与输入相符 |
| C 出站 | 输入草稿、回读、确认发送、核对出站 | 草稿回读结果、发送证据、通过状态 | 目标正确、回复完整，微信中出现对应出站消息 |

自动测试通过、API 返回 200、或找到控件都不能代替人工判定。
程序不代点 A/B/C 通过，不将“尝试发送”写成“发送成功”。
本版运行在人工验收模式：新消息自动进入 A 待审阅；后续每步由按钮明确执行。
没有无人值守跳过审阅的全自动发送模式。

## 2. 环境与目录

- Windows 本机已登录微信；本机已验证版本为 4.1.13.12，其他版本须重新校准。
- 测试对象使用独立聊天窗口，标题必须唯一；不要在测试中关闭、改名或切换其对象。
- 当前专用对象为 shanyan；扩展到其他联系人/群时，先由测试人员建立独立窗口并选择白名单。
- Python 路径 E:/project/bot/.conda/python.exe；不需要虚拟机。
- 模型配置为 config/deepseek.toml，当前模型名为 deepseek-v4-flash-vision-exp。
- data/deepseek.sqlite3 是原内核数据库，**不是模型文件或模型服务**。
- 验收记录单独保存在 data/acceptance/reviews.sqlite3，不重放旧内核的任务队列。
- API 凭证由既有 DPAPI 文件或 DEEPSEEK_API_KEY 环境变量提供，不在日志中打印。

首次安装/更新依赖：

```powershell
Set-Location E:/project/bot
& .\.conda\python.exe -m pip install -e '.[acceptance,dev]'
& .\.conda\python.exe -m pip check
```

Pillow 负责图片显示，zstandard 负责压缩消息文本，imageio-ffmpeg 提供 WXGF/HEVC 图片解码。
图片不是截图替代品，也不会从聊天正文读取任意文件路径或下载任意 URL。

## 3. 启动与本次微信校准

```powershell
& E:/project/bot/.conda/python.exe E:/project/bot/scripts/acceptance.py
```

1. 打开微信的 shanyan 独立窗口。测试图片时先打开/下载该图片。
2. 启动验收程序。初始不发送、不调用模型，只尝试读取候选窗口信息。
3. 如果提示微信重启、密钥绑定过期或未校准：在“重新校准的独立窗口标题”填 shanyan，
   点击“校准当前微信（无障碍开关＋本地密钥）”。
4. 校准会核对精确窗口/PID；预检唯一候选后设置进程内 Qt 无障碍开关，
   并只读提取该进程必要消息分片密钥。密钥经数据库页 HMAC 校验、DPAPI 加密保存。
5. 校准失败则保持关闭；不要把 windows.example.toml 的 verified 改为 true 来绕过。
6. 校准成功后刷新候选窗口，选择本次白名单，点击“启动 Bot / 连接所选白名单”。

校准不是发送操作，但无障碍开关作用于整个微信进程。此前已由用户明确授权。
停止校准会阻止后续步骤；已经发生的开关写入不会自动回滚。
群聊验收可在个人窗口校准完成后，从候选列表选择已打开的群独立窗口。
若群控件结构或分片密钥不满足条件，必须记录为未通过，不能推测兼容。

## 4. 白名单与新消息基线

候选窗口列表支持多选。“启动 Bot”只连接本次选中的窗口，为每个会话建立独立页签。
名单保存在 data/acceptance/allowlist.json；保存名单不保存启动状态。
修改名单时先停止并等待正在执行的操作结束，再重新选择并启动。

连接时把当前可读取消息设为基线，不自动处理历史消息。之后约每 2 秒轮询一次；
同一工作线程正在调用模型、解码图片或发送时，轮询等待该操作结束，故这不是硬实时系统。
需要历史测试样本时，使用页签上的“A 最近文字”“A 最近图片”或“A 最新消息”。
已有验收记录不自动重放；请用新消息测试，避免重复发送。

## 5. 文字完整测试流程

准备一条容易核对的消息，例如：`文字测试-01：请回复收到。`
由对方测试账号发送给当前登录账号，不要用本账号自己的出站消息冒充入站样本。

### A：读取并审阅

1. 等待对应页签出现样本，或点击“A 最近文字”读取历史样本。
2. 核对 A 区的发送者、时间、文字、换行/表情和原生消息键。
3. 与微信原消息逐项比较；此时 B 应显示尚未调用模型，C 应显示未输入、未发送。
4. 一致时点击“A 人工判定通过”，在确认窗口中确认；否则点击“本样本判定不通过 / 停止”。

A 通过之前，点击调用模型必须被拒绝。空文字、未支持类型或未取得图片不能通过 A。

### B：单独调用模型并审阅

1. A 通过后点击“B 调用模型”。只有此按钮执行实际模型请求。
2. 检查 B 区显示的模型、独立会话、本次输入及实际回复。
3. 检查回复未混入其他联系人上下文；核对内容、长度、语言和格式。
4. 满意时点击“B 人工判定通过”，在确认窗口中确认。

模型超时或失败时显示错误并停止，不自动拿模拟回复冒充真实模型结果。
超过配置发送长度上限的回复不直接发送，也不偷偷截断。
B 通过前，C1 输入操作必须被拒绝。

### C：输入、发送与最终审阅

1. 点击“C1 填入草稿”。程序先确认目标窗口和输入框为空，再写入已审阅回复。
2. C 区应显示“已填入并回读一致；尚未发送”。人工检查微信输入框中的实际草稿。
3. 目标与文字正确时点击“C2 确认发送”。确认窗口会列出会话和完整回复，点击确认才发送。
4. 程序重新核对目标、草稿、发送按钮及白名单，然后调用发送按钮。
5. 等待匹配的本账号原生出站记录；C 区显示证据后，仍为 C 待审阅。
6. 人工在微信中核对出站消息，点击“C 人工判定通过”。此时才进入 complete。

测试人员可以在第 3 步取消确认；取消不得产生发送。
本地出站记录只是本地发送证据，不证明服务器已交付、对方已读。
如果出现 uncertain，不得重新点击发送或重新运行同一队列碰运气。

## 6. 图片完整测试流程

1. 由白名单联系人发送一张易判定的图片，推荐明显的红/蓝两色图或简单文字图。
2. 在微信中打开该图，确保媒体文件已下载；程序仅在该会话附件目录内按消息摘要定位。
3. 等待新样本，或点击“A 最近图片”。首次解码可能需要较长时间。
4. A 区应显示真实图片预览；点击“查看本地图片”可用系统图片查看器核对。
5. 核对是否是同一张图；若说明为缩略图，必须记录分辨率限制，不能判定原图细节能力通过。
6. 点击 A 通过后再点击 B。图片以实际 PNG 内容块送入已配置视觉模型，
   图片没有附带文字时使用“请理解这张图片并回复。”作为测试提示。
7. 核对模型描述是否对应实际图片，然后按文字流程完成 B、C。

支持路径包括常见图片、部分 XOR/V2 加密图片及 WXGF/HEVC 解码。
图片上限为 8 MiB、解码像素上限为 2000 万；不支持的编码或无法验证的密钥必须失败。
若首次 A 显示未下载/解码失败，在微信下载原图后点“A 重读当前样本”；
此操作只允许 A 尚未通过的样本，不悄悄替换已经审阅并发给模型的图片。
语音、视频、文件等其他类型本版显示为未支持，不计为图片测试通过。

## 7. 隔离与异常测试矩阵

| 编号 | 操作方法 | 预期结果 |
|---|---|---|
| W01 默认关闭 | 打开程序但不启动 | 不调用模型，不写微信输入框，不发送 |
| W02 白名单外 | 非白名单联系人发一条独特消息 | 不进入验收页签、不调用模型、不回复 |
| W03 自发过滤 | 本账号在测试聊天发送一条消息 | 不作为对方入站消息触发新样本 |
| W04 历史基线 | 启动前放几条旧消息，再启动 | 不自动处理旧消息；历史按钮读取是明确例外 |
| I01 联系人隔离 | A 联系人告知代号“苹果”；B 问代号 | B 不应得到 A 的上下文；页签/请求会话标识不同 |
| I02 群聊隔离 | 群与私聊分别发测试文本 | 按原生会话分列；当前群内还按发送者隔离上下文 |
| I03 同文两条 | 同一联系人连续发送两条相同文字 | 原生消息键不同，分别可审阅；重复轮询不会重复同一条 |
| G01 阶段门禁 | A 未过直接 B；B 未过直接 C1；C 未发直接判过 | 均拒绝，不能越级 |
| G02 拒绝发送 | C2 确认窗口点击否 | 微信无新出站消息 |
| D01 草稿保护 | 微信输入框先留人工草稿，再点 C1 | 拒绝覆盖，保留原草稿 |
| D02 草稿变更 | C1 后人工修改草稿，再点 C2 | 拒绝发送；不得发送过时回复 |
| S01 停止 | B 请求期间或 C1 后按停止 | 不再进入新的写入；已在进行的操作等待结束，草稿不自动清除 |
| S02 移出白名单 | 停止后取消某会话，再启动 | 旧页签可保留记录，但不能调用模型或发送该会话 |
| R01 微信重启 | 退出重开微信 | 旧 PID/启动时间/句柄绑定拒绝使用，须校准 |
| R02 程序中断 | 在专用测试中中断验收程序 | 未完步骤取消；sending 恢复为 uncertain，不重发 |
| R03 上下文历史 | B 生成但 C 未人工通过，再发新样本 | 未完成回复不进入已通过历史 |
| M01 模型故障 | 使用隔离配置模拟超时/错误 | 显示失败，禁止自动发送兜底文字 |
| P01 图片故障 | 未下载/不支持/过大图片 | A 显式显示原因，不能通过，不能发占位图给模型 |

W02、I01、I02 必须由测试人员选择和准备测试对象；自动化测试使用合成对象，
不主动给真实的非白名单联系人或群发送消息来造测试数据。
有副作用的中断/故障试验只在专用测试窗口执行，先完成普通流程再开展。

## 8. 异常发送恢复

若程序退出后记录停在 sending，重启会标为 uncertain。先核对微信，绝不能自动重发。
需要程序只读辅助核对时，关闭验收窗口以释放实例锁，再运行：

```powershell
& .\.conda\python.exe scripts/acceptance_reconcile.py --title shanyan
```

脚本只查询指定会话中与原发送时间、发送者、文字匹配的出站记录。
唯一匹配时恢复到 c_review，重开面板并连接该会话后可看到记录，由人工判断 C。
零条或多条匹配仍保持 uncertain；不能把这两种情况自动判成功或自动重发。

如果微信重启使绑定失效，先在面板点击校准，再关闭面板运行核对脚本。
校准与核对不会将历史样本再次发送。

## 9. 自动化回归方法

```powershell
& .\.conda\python.exe -m pytest -q
& .\.conda\python.exe -m ruff check src tests scripts/acceptance*.py
& .\.conda\python.exe -m pip check
```

- test_acceptance.py：阶段门禁、历史隔离、人工标志、中断恢复与本地导出。
- test_acceptance_panel.py：真实 Tk 控件流程，模型/微信为替身；确认窗口由合成测试模拟。
- test_native_review.py：白名单拒绝、自发过滤、基线、停止与草稿保护。
- test_native_media.py：真实图片字节、XOR/V2、会话目录限制、WXGF/HEVC 解码。
- 原有测试继续覆盖内核、队列、UIA 控件契约、SQLCipher/WAL 和原生 ID。

这些测试不调用真实模型、不发送真实微信消息，不能算作人工 A/B/C 通过。
只读实机预检可单独运行：

```powershell
& .\.conda\python.exe scripts/acceptance_preflight.py --title shanyan
```

它把文字/图片样本写入 data/acceptance/read-preflight.json，所有人工通过标志保持 false。

## 10. 输出、报告与结束条件

面板点击“导出本地验收报告”，会生成 data/acceptance/review-日期时间.json。
报告包含实际消息、回复、阶段、发送证据及 A/B/C 人工标志；仅保存在本地。
reviews.sqlite3 的 review_events 表记录阶段变化和时间，可用于复盘操作顺序。

每个测试场景至少记录：日期、客户端/程序版本、对象类型、样本消息键、执行步骤、
预期、实际、人工结果、故障原因、是否实际发送、证据文件位置。
成功标准是所选样本 A/B/C 都经人工通过；存在图片/群聊未测、uncertain 或 failed 时，
总体结果只能写“部分通过/待验收”，不能写“全部通过”。

结束时停止 Bot，等待当前任务完成，再关闭面板。保留必要的本地审阅记录；
不要上传 data/、.secrets/、真实聊天截图、完整回复或密钥。
公开版本只包含源代码、合成测试及不含真实聊天内容的汇总报告。

根据本次用户确认，读取消息、模型调用、回复输入已通过测试，取消这三步的人工审阅。

发送仍保留两个明确操作：

1. 核对目标聊天和回复，点击“确认发送此回复”，在弹窗中确认。
2. 在微信核对发送结果，点击“人工确认发送通过”。

旧失败/不确定发送不会自动重放。自动阶段不会伪造 A/B 人工通过记录，

本次发送实现不再调用 UIA Invoke：以实时定位的按钮矩形计算客户区坐标，
向绑定的独立窗口 HWND 投递一次按下/抬起事件，不移动全局鼠标，不输入 Enter。
随后强制重读数据库寻找本账号新增、同文且唯一的消息。数据库短暂变化只重试读取，
不重试点击。超时或多条匹配均保留“不确定”，不能视为通过。

该发送路径已完成代码与模拟边界测试，**尚待用户在真实微信中点击确认并验收**。
启动后的默认状态仍为关闭，用户须主动连接白名单。
