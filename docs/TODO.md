# TODO 与待确认事项

这份清单明确区分已运行的基础架构和真实微信接入所需工作。代码中的同名编号指向这里。

| 编号 | 优先级 | 待确认/实现内容 | 当前行为与影响 | 验收条件 |
|---|---|---|---|---|
| T01 | P0 | 用户实际微信版本、UIA 控件结构及依赖兼容性 | `verified=false` 默认拒绝真实接入；没有通用已验证 profile | 在具体版本测试独立窗口、输入、发送及失败场景，保存版本报告 |
| T02 | P0 | 稳定消息/用户 ID、带时区时间、系统行/多媒体解析及离线补收 | 必需字段不满足则拒绝读取；只观察 UI 可见消息；启动建立基线会略过停机消息 | 重建 UI/重启后 ID 稳定，同文本不同消息可区分，测量刷屏漏收；无法满足则更换适配器 |
| T03 | P1 | 真正 @ 识别、群引用回复和多媒体类型支持 | UIA 只通过 `/问 ` 触发，普通文本回复；群 sender 必须稳定 | @ 与昵称正文可区分、引用对象正确、同名成员不串话 |
| T04 | P1 | 登录/客户端身份探测与进程重启后重新发现 | 手工 PID 配置，失效会停止新工作并报 poll_failed | 能唯一确认客户端及目标账号，不能误连另一个实例 |
| T05 | P1 | 自动识别人工接管和更完整管理界面 | CLI/PAUSE 文件手动暂停；不推断手机端人工回复 | 人工回复后待发任务正确取消，恢复行为清楚 |
| T06 | P1 | UIA 独立进程、卡死超时和可控退出 | 单专用线程可能被 OS 调用阻塞；watchdog 仅检测退出 | 故意挂死 UIA 后主进程仍可心跳，重启后发送中任务进入 uncertain |
| T07 | P1 | 邮件等外部告警与端到端健康检查 | 只有日志、状态和本地心跳，没有主动通知 | 掉线/积压/uncertain 有去重告警，正常时不刷通知 |
| T08 | P1 | 数据保留、磁盘容量、队列上限与去重墓碑 | 明文 SQLite/JSONL，日志已轮转；数据库无自动清理 | 可清理正文且不破坏重放去重，磁盘不足及时停止接收/告警 |
| T09 | P2 | 知识库、费用/token 预算、多版本数据库迁移 | 无 RAG，无费用硬预算；schema v1，未知版本拒绝 | 独立测试上下文预算、费用限制、升级和恢复 |
| T10 | P1 | 真实规模与长期运行目标 | 默认 2 个模型任务、2 秒发送间隔、5 分钟 TTL；未做真实微信负载测试 | 明确好友/群数量、日消息量、可接受漏收与人工恢复时间，完成至少一周试运行 |
| T11 | P1 | 微信图片入站、下载、受信任媒体目录与过期清理 | DeepSeek 文本/视觉 API 已实测；模型服务和 model-test 支持图片，聊天流水线仍仅处理文本 | 下载来源可验证、文件只从受信任目录读取、群图片触发与上下文隔离通过测试 |

P0 是启用真实微信前的阻塞项；P1 是长期运行应完善的事项；P2 是功能演进。
不将更改配置标志、通过 mock 测试或“客户端窗口存在”视为完成 P0。
