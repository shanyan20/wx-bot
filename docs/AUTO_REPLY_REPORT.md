# 双联系人自动回复测试更新

最新的并发调度修复与测试见 [多联系人调度修复](MULTI_CONTACT_REPORT.md)。

用户已确认此前真实发送的人工验收通过。本次将测试程序改为对“憨憨的小憨憨”和“shanyan”的新消息自动读取、调用配置中的 DeepSeek 模型、填入输入框并发送，不再逐条弹窗确认。

## 使用方式

1. 关闭旧版测试面板，保留这两位联系人的微信独立聊天窗口。
2. 使用项目的 `.conda/pythonw.exe -m wechat_bot.acceptance_panel --project E:\project\bot` 启动新版面板。
3. 两位已绑定联系人默认选中，点击“启动 Bot / 连接所选白名单”。连接时建立消息基线，之后收到的新消息才触发自动回复。
4. 各联系人标签页分别显示原始消息、模型回复和发送证据。点击“停止 Bot”停止后续处理。

本机已根据实际独立窗口生成 `data/acceptance/test_contacts.json`，保存上述两个名称与真实微信原生会话 ID 的绑定。该文件不上传 GitHub。运行时只展示匹配的私聊窗口，同名歧义、身份不一致会拒绝连接；旧版保存的白名单不会扩大这次授权范围。未打开的窗口不会被加入连接。

## 自动处理规则

- 文字和图片沿用已验收的读取、解析及模型调用路径；每个账号、会话独立保存上下文。
- 发送保持指定 HWND 的单次鼠标按下/抬起；先核对窗口、输入框文本和发送按钮，再检查原生数据库新增的本人出站消息。
- 只有发现匹配的出站消息，才记录 `auto_sent` 并纳入后续模型历史。此状态是程序证据验证，不伪造人工通过标记。
- 失败或结果不确定时停止，不自动重试发送；重启不重放已有消息。旧版待核对记录保持原状态。
- 自动模式关闭历史样本读取入口，避免历史消息被意外发送回复。启动仍默认关闭，启动后无需逐条确认发送。

## 验证结果

本次完整 Python 测试通过：166 项；Ruff 静态检查通过。新增与调整的测试覆盖两联系人全链路无需确认、后续消息历史延续且不串会话、白名单外消息不处理、同名/错误身份拒绝、重复消息不再次发送、停止后禁止发送，以及自动发送证据校验和重启恢复。原有发送超时、窗口定位和原生出站检查测试保留。

真实单次发送通过依据为用户本次反馈；本次自动流程测试使用模拟微信与模型，未主动给联系人发送额外测试消息。另外已在本机验证两位绑定联系人的窗口检查及原生消息基线建立均成功，此检查未调用模型、输入或发送。新版的连续真实来信测试需要在启动新版面板后观察本地证据。
