# 个人微信接入说明

2026-09-10：授权热激活后，指定窗口已暴露控件树，实际可验证字段已填写；
消息行唯一标识等条件仍未满足，禁止直接启用。见 [本机实测](NATIVE_ADAPTER_REPORT.md)。
后续接入路线见 [接入方案调整](ADAPTER_REDESIGN.md)。下文保留为旧实验性实现的契约说明。

## 当前实际可用范围

`mock` 已实现完整本地收发，用于验证业务核心。
`windows_uia` 是可配置的实验性实现，并非任何微信 3.x/4.x 的现成兼容驱动。
已进行指定独立窗口的实机控件检查，未向真实好友或群发送测试消息。

**微信未必通过 UIA 暴露稳定消息 ID、稳定用户 ID、精确时间和完整消息列表。**
这些字段不满足时，本实现应保持禁用，不能通过伪造标识或随意放宽校验来绕过。
可能需要自行开发经授权且可长期维护的接入插件；核心结构不依赖接入库。

## 实验性 UIA 的先决条件

1. Windows 登录用户有可交互桌面，微信已经人工登录。
2. 每个被监听的好友/群有独立聊天窗口，窗口不会被人工切换成别的会话。
3. `process_id + window_title` 能唯一定位窗口，`header_id/header_text` 能再次确认会话。
4. 消息列表可通过 AutomationId 找到，直接子节点为 `ListItem`。
5. 每条消息行的 AutomationId 为稳定消息标识，不能是空值、重复值或仅随 UI 重建的临时编号。
6. 每行可找到 sender/body/timestamp 三个唯一后代控件。sender 是稳定用户标识，
   timestamp 为带时区的 ISO 8601 时间，例如 `2026-09-08T12:30:00+08:00`。
7. 输入框支持 `get_value/set_edit_text`，发送按钮支持 UIA Invoke。
8. 新的己方消息可从列表观察到，能与发送前 ID 集合、正文及己方标识比对。

这些是适配器要求，不是已确认的微信客户端特性。
遇到时间分隔行、系统消息、多媒体行等不能按字段解析的情况，当前实现会停止该轮读取，
不会猜测它们的含义。真实客户端类型解析扩展参见 T02。

## 配置步骤

1. 先运行 README 的模拟流程并执行测试。
2. 安装可选依赖：`python -m pip install -e ".[windows]"`。
3. 用 Windows SDK 的 Inspect 等控件检查工具人工检查测试聊天窗口，记录控件结构。
4. 复制 `config/windows.example.toml` 为 `config/local.toml`，填写真实控件信息及 PID。
5. 将实测版本、控件树差异、失败表现记录到 `docs/VALIDATION.md` 或单独的版本报告。
6. 完成下方验收后才将 `windows.verified` 设为 `true`。
7. 初次启用只加入一个测试好友，使用 echo；确认后再测试群命令和真实模型。

`check` 只验证配置完整性，不证明 Windows 或微信兼容。
脚本不自动探测窗口、不导出控件树到日志、不自动启动微信或替用户扫码。
微信重启后 PID 会改变，需更新配置；自动发现及身份核对属于 T04。

## 群消息

统一 `Message` 支持可信 `mentioned=True`；UIA 实现目前总是提供 `False`。
因此真实 UIA 群聊只使用 `/问 ` 前缀，正文出现昵称不视为真正 @。
sender 无稳定用户标识时，不能安全隔离同名群成员上下文，应停用该接入。
回复目前是普通文本，不含原消息引用、不自动 @ 提问者；扩展见 T03。

## 启动基线与漏收边界

每次创建 UIA 适配器，首次快照只建立基线，不回复已有屏幕消息。
这样避免启动后批量回复历史，但会略过停机期间、首次快照前出现的消息。
仅能读取当前暴露的 UI 消息，虚拟列表未加载消息、快速刷屏、窗口关闭都可能导致漏收。
SQLite 只能保护已经读到的消息，无法修复微信未暴露的数据。
不自动滚动历史、不自动切换会话，以免改变视图或误定位。

## 新增适配器契约

实现 `adapters/base.py` 的四个异步方法：

- `poll()`：返回已验证的 `Message` 列表，稳定 ID 可去重，自发消息准确标注。
- `ack(batch)`：只有核心将消息提交数据库后才确认游标；可重放相同 ID。
- `send(job)`：使用 `conversation_id` 定位，返回可描述的 `SendReceipt`。
  确认未发送才抛 `NotSentError`；可能已发送必须抛 `UncertainSendError`。
- `close()`：释放线程、连接、窗口句柄等资源，不主动退出用户的微信。

在 `cli.build_adapter` 增加构造分支，并在配置校验中登记类型。
接入库版本、授权和真实能力要独立验证；不因其接口叫 `send` 就默认可靠送达。

## 实机验收

| 场景 | 通过条件 |
|---|---|
| 同一消息重复读取 | 只生成一个任务 |
| 同一人连发两条相同文本 | 两条独立 ID，各处理一次 |
| 同名好友或群 | 无歧义定位，无法定位时拒绝发送 |
| 同名群成员 | 身份不混淆，上下文隔离 |
| 己方消息出现 | 不触发自我循环 |
| 输入框已有草稿 | 不覆盖，不发送 |
| 发送按钮操作后失去窗口 | uncertain，不自动重发 |
| 客户端退出、锁屏、断网 | 不误发，异常可观察 |
| 重启、历史滚动、UI 重建 | 消息 ID 稳定，不回复已有历史 |
| 群快速刷屏、系统行、多媒体 | 明确支持范围和漏收率，无错误身份解析 |
